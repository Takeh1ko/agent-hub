# Замечания к ahub (с сервера)

Что хаб по умолчанию делает плохо или не делает — записывает оркестратор (Claude) по ходу работы, исправляет
владелец. Новое — сверху. Формат: дата · что видно · почему плохо · как исправить (предложение) · статус.

## 2026-10-28 · PlayerUP · agy не запускается с 14.10, а хаб показывает его рабочим
`/root/.local/lib/agy/agy` (обновился 14.10 03:24) падает сразу: «This binary was compiled with pclmul enabled, but
this feature is not available on this processor». Процессор VPS — `QEMU Virtual CPU version 2.5+` без `pclmulqdq`.
`ahub providers` при этом: agy found ✓ · enabled on, квота «5h 100% (resets 14.10 03:35)» — данные двухнедельной
давности, падение бинаря не видно; задачу на `gemini` можно поставить, и она упадёт уже в работе.
Предложение: `providers`/`doctor` запускают `agy --version` и показывают его ошибку; квоту с меткой старше суток
помечать как устаревшую; провайдер, который не запускается, не предлагать в `task new`. Статус: открыто.

## 2026-10-28 · PlayerUP · Задача на `spark` (Go) падает «нужна подписка Go», а `providers` пишет «paid Spark available»
T141 (`--model spark --effort xhigh`) сразу ушла в error: «An active OpenCode Go subscription is required to use Go
models». В `ahub providers` в это же время: «opencode-go: paid Spark available». Следом `spark-free` (T142/T143) больше

Предложение: проверять активность Go до постановки (отказ одной строкой при `task new`); при серии одинаковых
серверных ошибок провайдера сразу давать событие оркестратору, не тратя все повторы. Статус: открыто.

## 2026-10-17 · PlayerUP · Проверка слияния падает на задачах сайта: нет node_modules (T137)
`ahub accept T137` (фронтенд, узлы `tests/web/test_web.py::test_typecheck|lint|unit|build`) — «acceptance is red»
за 0.47 с, хотя в копии задачи все 4 узла зелёные. Проверка слияния идёт во временной копии
`<root>-wt/accept-T<n>` (`accept.py::_verify_merge`), куда не ставятся зависимости: хук `task_setup` там не
вызывается, а `web/node_modules` в git не лежит → `npm run …` падает сразу. Работник в своей копии ставил
`npm ci` сам (276 пакетов, долго и тяжело по памяти на 4 ГБ).
Обход на сервере (оркестратор): симлинк `/root/PlayerUP-wt/node_modules → /root/PlayerUP/web/node_modules` —
Node и npm ищут пакеты вверх по каталогам, его видят и копии задач, и `accept-T<n>`.
Предложение: (1) вызывать `task_setup` (или отдельный хук `verify_setup`) и во временной копии проверки;
(2) настройка проекта «общие каталоги зависимостей» (`shared_dirs = ["web/node_modules"]`) — хаб линкует их
в каждую копию и в копию проверки. Статус: открыто, обход действует.

## 2026-10-07 · Каталог уровней рассуждений отстаёт от модели: `--effort max` для Spark отклоняется
- **Видно:** `ahub task new --model spark --effort max` → «unknown reasoning level 'max' for model spark (valid: minimal,
  low, medium, high, xhigh)». При этом API Spark 1.3 (`opencode.ai/zen/go/v1/responses`, `reasoning.effort = max`)

- **Предложение:** уровни брать из живого каталога провайдера (или пробным запросом `ahub models check`), а не из
  зашитого списка; неизвестный уровень — предупреждение, а не отказ.
- **Статус:** открыто; обход — задачи на xhigh.

## 2026-10-06 · Работникам по умолчанию запрещено даже читать вне worktree
- **Видно:** opencode без настроек отклоняет любой доступ вне каталога сессии (`external_directory` → ask →
  в `run` «auto-rejecting»), включая чтение. Нужные для справки каталоги вне git (у PlayerUP — библиотека
  `playerok-universal/`, в worktree её нет) работнику недоступны, сессия обрывается (см. запись про T6 ниже).
- **Почему плохо:** чтение не опасно — смотреть код, логи, соседние библиотеки работник должен свободно; запрет на
  чтение только ломает задачи.
- **Предложение:** хаб сам пишет конфиг opencode для своих сессий (`OPENCODE_CONFIG`) с
  `permission.external_directory`: allow на чтение корня проекта (и списка `read_paths` из `.hub.toml`), ask/deny на
  остальное. Запись вне worktree запрещать отдельно — проверено на opencode 1.18.34: правило `permission.edit` с
  абсолютными путями (`"/root/PlayerUP/**": "deny"`) НЕ срабатывает, запись прошла; нужен другой механизм (проверка
  хаба после хода: изменения в корне проекта → тревога/откат, или песочница ФС).
- **Статус:** обход на сервере — `/opt/opencode-v1/bin/opencode` экспортирует
  `OPENCODE_CONFIG=/root/.local/share/opencode-v1/opencode.json` (allow `/root/PlayerUP/**`, остальное ask);
  запись туда запрещена только правилами проекта (`docs/agents/rules.md`).

## 2026-10-06 · `ahub nudge` в работающую сессию роняет задачу: «database is locked»
- **Видно:** `ahub nudge T5 "…"` во время работы исполнителя → через 2 с `settled: error (crash: Unexpected error
  database is locked)`. Задача упала, нужен `ahub continue`.
- **Почему:** nudge запускает второй процесс opencode в ту же сессию, пока первый жив; оба пишут в sqlite opencode.
- **Предложение:** nudge класть в очередь задачи и доставлять между ходами (после выхода текущего процесса) или через
  API работающего процесса; при занятой сессии — не запускать второй процесс. Ошибку `database is locked` считать
  временной: автоповтор, а не `error`.
- **Статус:** открыто; обход — не делать nudge в работающую задачу, писать замечания через `rework` после круга.

## 2026-10-06 · Отказ opencode «external_directory» обрывает сессию, хаб видит «нет коммита» и запрещает работу
- **Видно:** T6 (PlayerUP) через 30 с работы полез читать `/root/PlayerUP/playerok-universal/...` (каталог вне git,
  в worktree его нет). opencode: `permission requested: external_directory (...); auto-rejecting` (в
  `.ahub/logs/executor.log.stderr`) — сессия закончилась «ok». Ворота: `gate_no_commit` → repair-промпт «Do not research
  anything new. Add only what is missing» → работник честно ничего не сделал → `needs_decision` «waiting for you».
  Владелец увидел «задача снова упала».
- **Почему:** (1) хаб не читает stderr сессии и не распознаёт отказ в правах как причину; (2) repair после пустой
  сессии запрещает именно ту работу, которой не было; (3) в причине `needs_decision` нет настоящей причины.
- **Предложение:** распознавать `auto-rejecting` в stderr → причина «работник упёрся в права: <путь>» и повтор круга с
  подсказкой «этот путь вне копии, не ходи туда»; repair-промпт «ничего нового» — только если в копии есть изменения;
  при пустой копии — обычное продолжение задачи. Опционально: `allow_external = ["…"]` в `.hub.toml` (read-only
  каталоги вне git, нужные для справки) или копировать игнорируемые каталоги из списка в worktree.
- **Статус:** обход — `ahub rework` с явной отменой запрета.

## 2026-10-06 · Нет разрешений на уровне задачи — работники отказываются от живых проверок
- **Видно:** разведки T3/T4 (PlayerUP) не стали читать боевую БД, env и проверять прокси: «per worktree-only rule»,
  «sandbox rule forbids real data/secrets». Главные вопросы владельца остались без ответа, оркестратор доделал сам.
- **Почему:** у задачи нет поля «что разрешено». Разрешения можно только вписать прозой в спецификацию, а общие правила
  проекта (`rules`) их перебивают — модель выбирает осторожный вариант.
- **Предложение:** поле задачи `--allow "prod-db:read,live:playerok,logs,tokens:read"` (и в `draft`), которое хаб
  вставляет в промпт отдельным блоком «Разрешения владельца — важнее правил проекта», а ревьюеры не штрафуют за их
  использование. Отчёт разведки «не проверил, потому что нельзя» при выданном разрешении — повод для rework.
- **Статус:** обход — раздел «Разрешения владельца» в спецификации + пункт в `docs/agents/rules.md` PlayerUP.
