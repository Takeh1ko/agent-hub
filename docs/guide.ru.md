# agent-hub — руководство пользователя

[English](guide.md) · [Русский](guide.ru.md)

Что делает хаб в одном абзаце: оркестратор (Claude Code или любой CLI-агент) ставит задачу, хаб выполняет её
моделью-работником в отдельной копии репозитория, проверяет результат, отдаёт его на ревью другим моделям и будит
оркестратора, когда нужно решение. Это руководство — задачная версия этого описания: как поставить, как выбрать
модели, как ставить и смотреть задачи, сколько это стоит и что запускать, когда что-то не работает.

Про сам код — [ARCHITECTURE.md](ARCHITECTURE.md).

## Установка и первый запуск

```
pipx install ahub
ahub setup
ahub doctor
```

`ahub setup` проходит восемь шагов:

1. **Язык** — `en` или `ru`, записывается в глобальный конфиг.
2. **Проект** — корень git-репозитория. Мастер создаёт `.hub.toml` (схема v2) с полями, которые захочется поправить:
   `name`, `allowed_paths`, `worktrees`, `work_branch`, `python`, `[budget]`, `[timeouts]`, и регистрирует проект в
   `~/.config/ahub/config.toml`.
3. **Провайдеры** — все, которых знает хаб (opencode, `agy`, `codex`): найден или нет, есть вход или нет, заметка и
   подсказка по установке, если его нет. Вы выбираете, кого включить.
4. **Модели** — живая проверка (по одному крошечному запросу на модель) всех моделей включённых провайдеров с
   пометкой free / paid / plan и выбор умолчаний для ролей. `AHUB_PROBE=0` отключает проверку.
5. **Служба** — системная служба (systemd в Linux, launchd в macOS) или фоновый процесс.
6. **Claude Code** — навык `ahub`, блок в `CLAUDE.md` проекта и разрешение `Bash(ahub:*)`.
7. **Telegram** — по желанию, по умолчанию выключен; нужен `pipx install 'ahub[telegram]'`.
8. **Doctor** — полная проверка шагов 1–7 в виде сводки.

Флаги: `ahub setup --yes` берёт все умолчания без вопросов, `--claude` ставит часть для Claude Code не спрашивая,
`--service` ставит и включает системную службу, `--name` и `--deny` задают имя проекта и запрещённые в нём модели,
`--lang` записывает язык хаба.

`ahub doctor` — те же проверки по требованию: каждая строка говорит, что не так и что сделать, код возврата 1, если
что-то сломано. `ahub --json doctor` даёт машинный вид.

Служба ведёт очередь: `queued → preparing → working → checking → reviewing → … → done`, либо `needs_decision`,
`error`, `stopped`. Без системной службы её запускает `ahub service start` в фоне (`ahub service stop`), а
`ahub service status` показывает пульс, очередь и процессы задач. Процессы задач отдельные и переживают перезапуск
службы; задача, чей процесс умер, возвращается в очередь.

## Провайдеры и модели

```
ahub providers                      # таблица: найден, вход, включён, модели
ahub providers enable opencode      # его модели становятся доступны
ahub providers disable codex        # его модели уходят из всех меню ролей
```

Выключенный провайдер — это жёсткий переключатель: назвать его модель в задаче можно только с отказом и подсказкой
(`ahub providers enable <имя>`).

```
ahub models                         # меню каждой роли, ★ — умолчание роли
ahub models --all                   # все псевдонимы с провайдером и id модели
ahub models role reviewer --add mimo-flash --default
ahub models add mymodel --provider opencode --model-id opencode-go/mimo-v2.6-flash
ahub models check                   # по одному живому запросу на модель по умолчанию
```

Роли:

| Роль | Что делает |
|---|---|
| `executor` | работает над `code`: пишет код и тесты в копии задачи, коммитит |
| `reviewer` | панель ревью: новые сессии, вердикт каждого, споры и починка |
| `scout` | задачи `scout`: читает и отчитывается, ничего не меняет |
| `routine` | задачи `routine`: мелкие правки файлов, без приёмочных тестов |
| `observer` | следит за самим хабом: проверка кодом раз в 5 мин, моделью раз в 30 мин |
| `drafter` | превращает обычные слова в поля задачи (`ahub draft`) |

Как платить по провайдерам: бесплатные модели opencode не требуют входа и стоят $0; модели opencode Go требуют
`opencode auth login` и считаются за токены; `agy` тратит квоту аккаунта Google; codex тратит подписку ChatGPT.
Последние двое отдают токены и никакой цены, поэтому задача на них показывает `$0.000 Go`, а токены видны в
`ahub follow`.

## Задачи

```
ahub task new --kind code --title "добавить повтор в платёжный клиент" \
  --spec-file spec.md --paths "app/payments/**,tests/**" --accept "tests/test_payments.py"
```

| Тип | Результат | Ворота |
|---|---|---|
| `scout` | отчёт | отчёт есть и по форме; ничего не изменено |
| `code` | ветка + отчёт | есть коммит, дифф ⊆ `--paths`, приёмка зелёная под замком проекта |
| `routine` | правки + отчёт | есть коммит, дифф ⊆ `--paths` |

Флаги, которые стоит знать: `--paths` (разрешённые файлы, глобы через запятую), `--accept` (узлы pytest, которые
должны пройти), `--model` (псевдоним, иначе умолчание роли), `--budget` (доллары Go на всю задачу) и
`--budget-usd` (реальные деньги), `--after T3,T4` (начать только после принятия этих задач), `--review` /
`--rounds` / `--no-review` (панель ревью), `--time-limit` (минуты), `--resources` (сделать задачу эксклюзивной),
`--draft` (создать черновик, а не задачу).

Задача проверяется до того, как потратится хоть копейка: разрешённые файлы должны попадать в `allowed_paths`
проекта, файлы для чтения должны существовать, приёмка должна собираться, модель должна быть доступна. Отказ
приходит с причиной.

Обычными словами, из терминала:

```
ahub draft new "добавить повтор в платёжный клиент, тесты в tests/test_payments.py"
ahub draft list
ahub draft start 1        # без старта ничего не запускается
```

Решения (везде принимают метку задачи):

```
ahub accept T12                       # scout/отчёт — принят; code — слито --no-ff, приёмка повторена, откат при красной
ahub rework T12 --notes "…"           # назад работнику, та же сессия, с вашими замечаниями
ahub reject T12 --reason "…"          # отклонено, копия задачи удаляется (--keep оставляет)
ahub continue T12                     # после ошибки или остановки
ahub stop T12                         # попросить работника свернуться
ahub extend T12 --paths "docs/**"     # разрешить больше файлов
ahub budget T12 --add 1               # добавить денег, задача снимется с бюджета сама
ahub model T12 mimo-flash             # другая модель на следующий круг
ahub task edit T12 --spec-file spec2.md   # новое техзадание, в новой сессии
```

## Наблюдение

```
ahub status                # L1: строка на задачу с ограничением по байтам (остальное — `ahub top`)
ahub status T12            # L2: состояние, модель, деньги, сводка, следующие команды
ahub result T12            # L2, тот же вид задачи, что `ahub status T12`; --full — result.json и весь отчёт (L3)
ahub diff T12              # дифф от базы
ahub follow T12            # живая расшифровка: промпты, текст, вызовы инструментов, результаты
ahub log T12               # сырой лог сессии
ahub history -n 20         # недавние задачи с исходом и ценой
ahub top                   # терминальный экран: задачи, пульс, деньги, события
```

  root-level conftest.py and adding one would be outside the allowed file list.…

`ahub follow T12` печатает промпт и ход по мере их появления и следит дальше, пока задача не покинет активное
состояние. `--role` выбирает сессию исполнителя или ревьюера, `--round` — номер круга сессии, `--full` показывает
промпт целиком и все строки результата, `--no-follow` печатает один раз и выходит.

`ahub nudge T12 "используй готового помощника"` отправляет сообщение в работающую сессию: текущий ход прерывается,
та же сессия продолжается с вашим текстом. Это работает, только пока процесс задачи жив; иначе одна строка и код 2.
В `ahub top` то же самое — `m` в режиме управления (`c`), `M` меняет модель, `b` бюджет, `o` сужает таблицу до
одного проекта, `t` открывает расшифровку, `?` показывает клавиши.

Взгляд оркестратора:

```
ahub watch        # поток событий для Monitor в Claude Code
ahub wait         # блокирующе: возвращается по событию или по --timeout
ahub ack 12 13    # подтвердить принятые события
```

Строки событий начинаются со стабильного кода: `DONE`, `DECISION`, `ERROR`, `OWNER`, `ANSWER`, `ALARM`. Они хранятся
до подтверждения, поэтому перезапуск их не теряет. `ahub inbox`, `ahub questions`, `ahub ask`, `ahub say` и
`ahub alarms` — человеческая сторона того же канала: ваше сообщение становится событием `OWNER` для оркестратора,
вопрос с кнопками — событием `ANSWER`.

Telegram (по желанию, `pipx install 'ahub[telegram]'` и токен в конфиге): любой ваш текст становится сообщением
для Claude; если живой сессии Claude для этого проекта нет, хаб её запускает. Сообщение принадлежит проекту —
префикс проекта в тексте (`agent-hub: …`, `по agent-hub: …`) либо проект, выбранный через `/project`; `/tasks`
показывает состояние только на чтение. Бот ставится отдельной службой рядом со службой хаба.

## Деньги и бюджеты

Хаб считает деньги так, как их сообщает провайдер: сессии opencode несут токены и цену, поэтому задача показывает
`$0.096 Go of $1.50 budget`. `agy` и codex отдают токены и никакой цены, поэтому их задачи показывают
`$0.000 Go`, а токены по шагам видны в `ahub follow` — сколько они стоят, это квота аккаунта.

* `--budget` — бюджет Go на всю задачу, включая ревью. `--budget-usd` — бюджет реальных денег (по умолчанию 0,
  траты запрещены).
* На 80 % хаб пишет событие в журнал; на 100 % работника просят сохранить результат и остановиться, а задача
  уходит в `needs_decision` с причиной. Ничего не убивается посреди записи.
* `ahub budget T12 --add 1` повышает бюджет, и задача возобновляется сама.
* `ahub cost` показывает деньги собственных сессий хаба по проектам и моделям (`--all`, `--since YYYY-MM-DD`).
  `ahub top` показывает те же числа в шапке, по группам проектов.

Настоящие цифры по задачам этого репозитория и тарифы, которые за них платили, — в README.

## Продвинуто: прокси на провайдера, песочница Codex

По умолчанию процесс каждого провайдера наследует окружение хаба, поэтому один системный прокси (`HTTPS_PROXY` и
подобные) действует на всех. В `~/.config/ahub/config.toml` у провайдера может быть свой — один через прокси, другой
напрямую:

```toml
[providers.opencode]
proxy = "http://127.0.0.1:8080"      # https_proxy/http_proxy/all_proxy для процесса этого провайдера
no_proxy = "localhost,127.0.0.1"

[providers.agy]
proxy = ""                            # пустая строка = явно без прокси (унаследованные переменные убираются)
```

Правило для каждого ключа: нет ключа — переменная наследуется как есть, `""` — явно нет (переменная убирается),
значение — переменная ставится; `proxy` задаёт `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` и их строчные варианты,
`no_proxy` — `NO_PROXY`/`no_proxy`, ключи друг на друга не влияют. Принимаются только http/https/socks5/socks5h.
Собственные процессы хаба и Telegram-бот работают как раньше (`[telegram] proxy` — отдельно). `ahub doctor`
показывает свой прокси каждого провайдера и отвечает ли он.

В этой же секции ключ `sandbox` для Codex — OS-песочница, в которой работает воркер:

```toml
[providers.codex]
sandbox = "workspace-write"     # read-only | workspace-write (по умолчанию) | danger-full-access
```

В `workspace-write` инструменты читают всё, но пишут только в копию задачи (это обеспечивает ядро). На Ubuntu 24.04
AppArmor запрещает непривилегированные user namespace, нужные bubblewrap, и тогда codex молча не выполняет ни одной
команды, а ход выходит пустым — `ahub doctor` распознаёт этот случай и даёт обе починки в одной подсказке: разрешить
namespace (`sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` и файл в `/etc/sysctl.d/`, чтобы
навсегда — решение администратора) или поставить `sandbox = "danger-full-access"`, где codex держат копия задачи и
ворота приёмки, как opencode и agy. Системные настройки хаб сам не меняет.

## Язык

`ahub --lang ru` (также `en`) переключает язык вывода одной команды; `ahub setup --lang ru` записывает его в глобальный
конфиг как `lang = "ru"`. `AHUB_LANG=ru` перекрывает всё для одного процесса. Если нет ни того, ни другого, решает
локаль (`LANG`, `LC_ALL`, `LC_MESSAGES`, начинающиеся с `ru`), иначе английский.

Промпты работника и панель ревью пишутся по-английски, чтобы модель поняла их в любом случае; отчёты и все
человеческие поля результата — на языке хаба. Коды событий не переводятся — навык Claude Code их разбирает.

## Если не работает

| Симптом | Что запустить |
|---|---|
| Что-то в установке сломано или провайдер не отвечает | `ahub doctor` — каждая строка это симптом и починка |
| Задача отклонена с `no model 'spark'` или `provider opencode is off` | `ahub models --all` — список псевдонимов; `ahub providers enable opencode` — если провайдер выключен |
| Бесплатная модель перестала отвечать (лимит или её убрали из каталога) | `ahub models check`, затем `ahub models role <роль> --set-default <псевдоним>` |
| Задача слишком долго в одном состоянии | `ahub follow T12` — посмотреть, что делает работник; `ahub nudge T12 "…"` — направить; `ahub stop T12` и `ahub continue T12`, если перезапустить |
| codex молча не выполняет команды на Ubuntu 24.04 | `ahub doctor` называет причину: либо разрешить user namespace, либо `sandbox = "danger-full-access"` |
| Провайдер установлен, но входа нет | `ahub doctor` показывает точную команду: `opencode auth login`, `agy` (аккаунт Google), `codex login` |
| Не выполняется вообще ничего | `ahub service status` — очереди нужна живая служба; без системной службы `ahub service start` |
| Оркестратор не увидел событие | оно не потерялось: `ahub inbox`, `ahub status`, а `ahub ack` — только после решения |
